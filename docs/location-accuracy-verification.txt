Location accuracy repair — 14 November 2026

Diagnosis
The first browser location could have kilometres of uncertainty. The old picker
immediately used it as the campus centre. The punch card treated every failed
check as Outside range, assumed Within range before any reading, and replaced
location errors with Location is turned off. These messages were incorrect.

Changes
- Shared bounded high-accuracy watch: request only on user action, maximumAge 0,
  wait up to 20 seconds for the configured accuracy, and stop immediately on a
  precise fix, permission denial, cancellation or deadline. No background tracking.
- Keep actual device coordinates, timestamp and reported uncertainty. Ignore stale,
  non-finite and impossible readings. Never invent accuracy or use the saved campus
  coordinates as a teacher's device location.
- Punch flow shows progress, rejects failed local checks before sending a POST,
  and still uses the existing authoritative server validation for accepted readings.
- Explicit not-checked, inaccurate, expired, uncertain-boundary, outside and inside
  states. Preserve real errors rather than claiming location is turned off.
- Campus current-location action only moves the pin when accuracy is within both
  school maxAccuracy and half the selected radius. Coarse readings show a dashed
  uncertainty circle and leave the selected pin unchanged. Manual map placement remains.
- Keep tile-loading errors separate so they cannot overwrite accuracy warnings.
- Location badges wrap on small screens.

Remaining physical-device check
Browser/device location quality cannot be guaranteed by application code. If the
device continues reporting 3333 m uncertainty, it cannot establish presence within
a 100 m campus. Verify the school pin on the actual building, use a GPS-enabled
phone with precise location and site permission, and retry inside the campus.
Existing pins saved from coarse readings are not automatically relocated.
Browser tests use simulated positions, not a physical GPS device.
