School-owned staff login and HR corrections — 20 October 2026

Behavior
- Teachers/Staff & HR directory now offers Enable login for active, unlinked staff.
  An authorized school administrator enters email/password and selects a role.
  The account, active school membership and staff link are created atomically.
  No platform administrator step is required. Existing links show Login linked.
- Requires staff.manage and memberships.manage; role selection requires roles.view.
  A role cannot exceed the acting administrator's grants. Owner roles are excluded.
  Cross-school access, CSRF failures and attempts to overwrite an existing global
  account are rejected. Passwords use the existing bcrypt helper; neither passwords
  nor hashes are returned or audited.
- Existing-account linking and membership role/suspension controls remain available.
- Departments have Add Department, Edit and Delete actions with explicit dialogs.
  Rename updates matching staff departments in the same transaction and increments
  profile revisions. Historical approved payroll snapshots are preserved.
  Delete rejects assigned staff (including archived profiles) until reassigned.
  Names are compared case-insensitively; duplicate names and stale writes are rejected.
- Department, role, staff and status labels use normal capitalization for display.
  Email addresses, codes and identifiers are preserved.
- Payroll continues to use saved payment day, deduction basis/divisor and work calendar.
  Changed settings make previous drafts stale; recalculate before approval.
  Approved payroll remains immutable rather than being silently recalculated.
- Punch-out now considers the configured closing time: an early departure requires
  administrator review even if the minimum duration was reached.
  Existing geofence, working-day, late-arrival and leave-approval checks remain.

API additions
POST /api/v1/schools/:schoolId/hr/staff/:id/login
  {email, password, roleId}
PUT /api/v1/schools/:schoolId/hr/departments
  {revision, action: add|rename|delete, name, previousName?}

No migrations, new indexes, dependency changes or configured-school database writes.
Use the existing testteach role when enabling the teacher login. It already has
Own attendance and salary. After creating the login, configure Salary setup with
Teacher punch in / out, then sign in with that teacher's email/password.

Scope limits
This does not add email invitations, password-recovery/reset workflows or bank
transfers. Existing global accounts cannot be claimed or reset by another school.
Physical GPS testing and actual school-account creation were not performed.
The browser/DB tests use isolated fixtures. Demo remains on its local repository.
