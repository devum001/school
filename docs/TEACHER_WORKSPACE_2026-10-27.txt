Teacher workspace, campus map and punch enforcement — 27-10-2026

Implemented
- Non-owner accounts linked to a teaching staff profile receive only their active
  class/section assignments in Overview and Student Attendance, even if their role
  includes school-wide overview.view or student-attendance view/manage permissions.
  Section teacher designations also count as assignments. No assignments means an
  empty workspace; there is no fallback to all classes or demo records.
- Teacher overview reuses the existing dashboard and student charts, with staff
  summary cards removed. Its API response omits staff profiles and staff attendance.
- Student attendance preselects an allowed class/section. Other classes/sections
  are absent from dropdowns. Staff Attendance is hidden and its direct UI route
  redirects for non-owner teachers. School owners retain their existing access.
- Student attendance writes require the teacher's open punch for the CURRENT school
  date, checked inside the existing tenant transaction. Missing punches, previous-day
  punches and completed punches cannot unlock saving. Global management permissions
  do not bypass this check for a linked non-owner teacher. Existing date/revision,
  assignment, tenant, CSRF and audit protections are retained.
- Sidebar Punch in & out opens /staff/punch in the main content area. The page shows
  school-local time, school hours, recorded arrival/departure and elapsed duration.
  Location diagnostics explain distance, allowed radius, measured GPS accuracy and
  required accuracy. The previous sidebar card was replaced, not kept as a second
  punch control. Existing demo punching remains in the demo workspace.
- Work & Leave location editor uses a draggable map pin, click-to-place, current
  location, accuracy circle, visible allowed-radius circle, presets and slider.
  Fine-tune coordinates remains available. Existing 25–1,000 metre limits and
  server geofence/accuracy/leave/workday rules remain authoritative.
- New GET /api/v1/schools/:schoolId/hr/punch-status requires attendance.self and an
  active, unambiguous staff/account link. It returns only that person's punch status.
  It includes the school timezone, current server time, school hours and campus rules.
  It avoids downloading the payroll workspace. Status refreshes only while the punch
  page is open (once per minute, on focus after 30 seconds, and after a punch).
  Opening the page does not request GPS; only Check my location and Punch actions do.

Try it locally
1. Install frontend dependencies with npm ci (Leaflet 1.9.4 is now included), then
   restart frontend and backend. Keep VITE_APP_MODE=live for this test.
2. As school owner, open School settings > Staff & Payroll > Work & Leave, edit the
   rules, add/edit the campus, use current location or move the pin, choose the
   radius and save. Review device accuracy instead of assuming GPS is exact.
3. Link a school login to the teacher profile and assign the teacher to the active
   academic year's class/section (for example, class 10 / A). Grant Overview or
   teaching.self, attendance.self, and student-attendance.assigned (or the relevant
   view/manage permissions). Existing custom roles are not rewritten automatically.
   If a saved employment attendance policy is manual/none, change it to punch for
   the applicable month. A newly linked teacher otherwise uses the existing default.
4. Sign in as the teacher in another browser/private window. Overview should show
   only assigned students, with no staff cards. Attendance should show only Student
   Attendance and the allowed class/section choices.
5. Open Punch in & out from the sidebar. Before punching, marking and saving are disabled. Outside the campus, punching
   is rejected. Inside the radius with sufficient GPS accuracy, Punch in enables
   student attendance. Punch out disables it again. Open My attendance & salary
   to verify the teacher's own calendar. On mobile, open navigation and choose Punch in & out.

Deployment and configuration
- Deploy both repositories together. No database initialization/migration script is
  required for this change. No real database records, .env values or credentials
  were changed, and no Atlas connection was made for verification.
- The map defaults to OpenStreetMap HTTPS raster tiles with attribution. Optional
  VITE_MAP_TILE_URL and VITE_MAP_ATTRIBUTION are documented in .env.example.
  Production map service selection should follow the provider's usage policy:
  https://operations.osmfoundation.org/policies/tiles/
  Do not put secret provider keys in VITE_* variables, which are public client code.
- Browser geolocation needs permission and HTTPS outside localhost. Device/location
  accuracy varies; a browser cannot guarantee spoof-proof physical presence.
- The test browser uses simulated coordinates; actual school GPS and real mobile
  device permission behavior still need a field check. The dedicated map test mocks
  tile images and verifies pin/radius controls and saving, not real-world map imagery.
