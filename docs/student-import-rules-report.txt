Student import dates, identity rules and presentation repair — 19 October 2026
Updated after the section-based roll-number clarification.

Behavior
- Calendar dates display and accept DD-MM-YYYY. Shared date/time fields show DD-MM-YYYY HH:mm. Native calendar selection and keyboard entry remain available.
- APIs and database dates remain ISO for comparisons and existing clients. Both DD-MM-YYYY text and genuine Excel dates are accepted in roster imports; legacy ISO workbooks remain supported. Invalid calendar dates and future birth/joining dates remain rejected.
- Date columns in CSV/XLSX downloads and the backend import report use DD-MM-YYYY. Identifiers that resemble dates are not reformatted.
- Names and guardian names may repeat. Admission Number is the school-local student identifier, compared using the existing case/whitespace normalization.
- Roll Number is unique per school + academic year + class + section. Different sections of the same class, and different classes, can reuse a roll number. For a sectionless class, rolls are unique within that class/year. Both workbook duplicates and conflicts with saved enrollments are checked.
- Live API writes retain school locking, transactions, permission checks, CSRF and audit behavior. The model index provides database-level enforcement after the maintenance step below.
- Removed the import preview's Result column. Original spreadsheet columns remain. Validation messages appear with the row, and import outcomes remain available through progress counts and Download import report. These are import statuses, not academic marks.
- Person names/descriptive roster text display in Title Case, such as Rahul Kumar. Admission numbers, roll numbers, emails, phone numbers and section identifiers are preserved. Stored historical profiles are not bulk-renamed.
- Fresh demo seeds number each section independently. Existing browser data is preserved and never renumbered. Academic result matching remains section-aware so equal rolls in different sections map to the correct students.

Database maintenance (NOT run against your configured database)
From /home/devendra/scholl backend/type-ORM-backend-Node:
  ./node_modules/.bin/ts-node commands/migrate-optional-sections.ts --preflight
During maintenance, only if preflight is ready:
  ./node_modules/.bin/ts-node commands/migrate-optional-sections.ts --apply
Preflight reports only readiness and duplicate-group counts within each section (or sectionless class). Apply installs the school/year/class/section/roll unique index before removing the obsolete class-wide index and the older index missing classId. It does not delete, renumber or rewrite students. Run this if the earlier class-wide index was installed, or if the optional-section index has never been installed. The earlier migrate-class-roll-numbers.ts command remains a compatibility alias for the corrected section-scoped maintenance flow; it no longer installs a class-wide restriction. No new API endpoint or environment variable is required.
