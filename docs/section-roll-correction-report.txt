Section-scoped roll-number correction — 19 October 2026

The current user rule replaces the earlier class-wide restriction:
- Class 10-A roll 7 and Class 10-B roll 7: allowed.
- Two Class 10-A students with roll 7 in the same academic year: rejected.
- Different classes can reuse roll numbers.
- A class without sections has a single roll-number scope for that academic year.
- Admission numbers remain unique across the school. Names may repeat.

Implementation
Frontend saveStudent and workbook validation now compare school, year, class and section. Excel instructions state the same rule. Fresh demo sections again number independently; existing localStorage records were not renumbered. Academic marks tests verify correct matching for equal rolls in different sections. The live browser import fixture now uses roll 42 in both sections A and B of Class 10.
Backend workbook duplicate checks normalize both class and section labels. Saved-record checks include sectionId (null/missing for sectionless classes). The unique index includes schoolId, academicYearId, classId, sectionId and rollNumber.
The existing optionalSections maintenance routine now installs that index before dropping the known obsolete class-wide and missing-classId roll indexes. The earlier classRollNumbers helper delegates to this routine so the previously documented command cannot reinstall the superseded rule. Unrelated indexes and student records remain unchanged. Tests cover rejection of same-section duplicates, permitted cross-section repeats, import dates, admission uniqueness, and safe/idempotent index correction.

Configured database
No connection to the configured database and no migration application were performed. If the earlier class-wide index was installed, use the corrected maintenance flow from the backend repository:
  ./node_modules/.bin/ts-node commands/migrate-optional-sections.ts --preflight
During maintenance, if preflight is ready:
  ./node_modules/.bin/ts-node commands/migrate-optional-sections.ts --apply
The old migrate-class-roll-numbers.ts command also delegates to the corrected routine. Neither command renumbers or deletes students.
