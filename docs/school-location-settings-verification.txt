School Location settings — 14 November 2026

User flow
School settings > General > School Location, beside School Calendar & Holidays.
Add/Edit location supports: map click, draggable pin, current device location,
manual Latitude and Longitude, and a pasted decimal coordinate pair. Radius is
shown on the map, with slider and presets. Saved campuses can be edited/removed.
Test current location checks the saved policy only; it never records attendance.
Existing campus records remain in the existing staff_hr_settings collection.
No migration, seed, environment change or dependency installation is required.
Restart/update the backend and refresh the frontend to use the new endpoint.

Phone coordinates
On your phone at school, open Google Maps, enable precise location, use its
current-location button, then touch and hold the actual school building to drop
a pin. Copy its decimal latitude, longitude (latitude first) into the new form.
Check the pin and radius before saving. The Google Maps help link is on the page:
https://support.google.com/maps/answer/18539
Alternatively open this school's settings on the phone and use current location.
Browser location on a phone needs the app served over HTTPS and location permission;
a laptop localhost address is not the same server when opened on a phone.
Manual campus coordinates do not substitute for a teacher's device location.
A 3333-metre uncertainty reading still cannot establish presence in a 100-metre
campus; real device accuracy cannot be guaranteed by application code.

Implementation
Shared SchoolLocations UI with typed demo/live adapters. Demo uses its existing
local repository; live uses authenticated GET/PUT /schools/:schoolId/hr/locations.
Read requires school.profile.view. Writes retain the existing payroll.manage
permission, CSRF and school-scoped transaction/audit enforcement. General settings
must be visible to the configured role. Owner accounts have these permissions.
The response includes only schoolId, revision, locations and maxAccuracy.
Writes preserve payroll, leave and timetable fields, reject stale revisions, and
validate ranges. Existing Work & Leave location forms moved to the General tab;
a link remains there so users can find the new location. Map edits participate
in the existing unsaved-changes confirmation. Errors remain at the form bottom.
The read performs one location-settings query after the normal authorization checks.
