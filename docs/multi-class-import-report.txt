Optional sections and mixed-class Excel import — 2026-10-19

Implemented
- Selected numeric class labels use raised ordinal suffixes: 1st, 2nd, 3rd, 11th, 12th.
  Stored school class names remain unchanged. Native selector options retain those names.
- Class setup accepts zero sections. Individual admissions and Excel imports can enroll directly
  in a class without creating synthetic section records. Sections remain required when the
  selected class actually has active sections; unknown sections are rejected.
- The template now has ten columns: Student Name, Admission Number, Birth Date, Guardian Name,
  Relationship, Parent Mobile, Address, Roll Number, Section, Class.
- One workbook routes rows to multiple existing classes in the current school/academic year.
  Class 12, Grade 12, 12 and 12th match the same numeric level. Unknown or ambiguous matches
  are errors, not automatic class creation. Custom class names still match normalized names.
- Live Excel import opens in a dialog, with scope/matching controls, a file picker, a visible
  Preview import button, row validation/correction, and Confirm import. The preview remains
  available after refresh. Accidental closure of a selected workbook is guarded.
- Demo uses the existing import dialog with a Class preview column, template download and
  Import students button. Its older class-scoped workbooks without Class remain supported.
- Whole class / individual section / No section student filters use the same saved-enrollment
  scope as their counts. This includes withdrawn enrollments, shown with their status, and
  inactive students in demo. Archived sections containing enrollments remain visible for review.
  Class totals include students enrolled directly without a section. Counts refresh after import.
- Existing live nine-column saved import jobs, row corrections and single-student API contracts
  remain supported; new multi-class jobs use the explicit school-students-v2 format.

Required maintenance on existing backend databases (NOT executed against your database)
Run from /home/devendra/scholl backend/type-ORM-backend-Node during a maintenance window:
  ./node_modules/.bin/ts-node commands/migrate-optional-sections.ts --preflight
  ./node_modules/.bin/ts-node commands/migrate-optional-sections.ts --apply
The old unique roll-number index omits classId. For students with no section, that would make
roll 1 conflict across different classes. This command creates the class-aware unique index
first, then removes only the known obsolete index. It does not delete or rewrite any records.
It checks duplicate groups first and is repeatable. Until it is applied, class-only enrollment
returns a clear prerequisite error; existing section-based enrollment continues working.
New empty databases initialized from the current models already get the correct index.
No new environment values, secrets, packages or lockfile changes are needed.
