# Connected fees, salary and teacher records

Teachers is a teaching staff directory with Overview and Documents only. It projects the shared Staff & HR employee record. Existing academic assignments remain stored, but are not surfaced or required by this profile. Staff & HR contains All Staff, Attendance, Leave and Salary. Full absences count as 1 leave, half-days as 0.5, and late arrivals do not deduct salary. Monthly cycles start on the configured payment day. Leave deduction uses basic salary divided by the number of calendar days in that cycle; both deduction switches and the Deduction component must be enabled.

Student fee setup supports One Time and unequal, manually entered Installments. Amounts are integer paise; total must equal the installment sum. Obligations remain the sole source of amounts and dates. Fee-plan edits freeze legacy FIFO allocations so date changes cannot move existing payments. Paid installments cannot be removed or reduced below paid amounts. Students with newly recorded receipts must be made inactive rather than deleted.

A fee payment allocates to a chosen pending installment or oldest pending charges, records transaction metadata, and freezes a numbered receipt snapshot. Salary confirmation records a single full net amount per staff/cycle, with gross, deductions, leaves, dates, mode, reference and slip snapshot. Duplicate staff/cycle payments and duplicate nonempty references are rejected. Changing future settings, names or attendance does not rewrite past documents. The Overview cash balance subtracts actually recorded salary payments; planned salary remains separately visible.

Templates contains Fee Receipt and Salary Slip only: six PNG layouts each and an accent color. The selected design, school/logo and live payment details are captured at confirmation. Printing opens only the rendered document. Download generates a one-page A4 PDF containing the rendered image. It is a raster PDF, not searchable text. Historical legacy payments without snapshots show a reconstructed receipt using retained current record data and a LEGACY number; this is not an original immutable receipt.

Teachers and students share a typed document uploader for PDF/PNG/JPEG/WebP, validated file headers and bytes, categories, download and confirmed deletion. Photos are resized locally. Each document is limited to 2 MB; the browser storage quota still limits the overall workspace. Save failures keep current in-memory state unchanged and display an error. This local demo is not suitable for production storage of sensitive identity documents.

Notifications keeps Student Absent, Low Attendance, Fee Installment Due, Fee Installment Overdue, Event / Announcement and Compose Notice. Due installments are shown within seven days; overdue begins after the due date. Each pending charge has its own reminder with outstanding amount; cards count unique students. Payment updates/cancels pending alerts. All system alerts wait for review; explicit notices may still be scheduled. Guardian contacts receive student notices, with no guardian/student login or In-app target. Existing old history and templates are retained for compatibility.

All writes pass through repository.ts, and local state is read via useSchool/useSyncExternalStore. No API, gateway, payroll transfer or external message is implemented. Received/recorded-by uses the current principal demo identity. Later backend integration needs authenticated staff identity, server-authorized tenant scoping, atomic ledger transactions, idempotency keys, numbering, database/file storage, actual delivery adapters and reliable job scheduling. Frontend status/configuration is not a security boundary or bank confirmation.
